# Event data schema

The demo emits one JSON object per event:

| Field | Meaning |
| --- | --- |
| `eventId` | Random event identifier. |
| `studyId` | Identifier for the configured study. |
| `participantId` | Pseudonymous demo participant identifier. Replace its source and policy per protocol. |
| `eventType` | Event category such as `route-visited`, `answer-action`, or `study-feedback`. |
| `occurredAt` | ISO-8601 timestamp generated by the browser. A production system should define its authoritative clock and time zone. |
| `data` | Event-specific fields. Keep this allow-listed and minimised. |

`analysis/process_events.py` validates the common fields and flattens known fields into a CSV. Unknown nested values are not copied into output. The sample file under `analysis/data/sample/` is synthetic.

Before adapting the schema, decide whether each field is necessary, whether it can identify a participant, whether it should be collected at all, and whether the approved protocol permits it. Do not assume pseudonymous IDs make a dataset anonymous.
